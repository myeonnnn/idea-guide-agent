# 프로젝트: 아이디어 검증 & 프로토타입 로드맵 에이전트

## 한 줄 정의
아이디어 입력부터 시장조사, 가설 검증, MVP/MLP 목표 설정, 비즈니스모델 가정까지
전 과정을 안내하는 **대화형 AI 에이전트**. 핵심 차별점은 결과물의 신뢰도를 담보하는
**자가검증(self-verification) 루프**.

## 왜 만드는가 (문제 정의)
- 기존 "AI 아이디어 검증 도구"(ValidatorAI, IdeaProof, DimeADozen, FounderPal 등)는
  빠른 리포트 생성에 최적화되어 있고, 결과물의 사실 검증 장치가 약함
- LLM이 생성한 시장 규모/통계/근거가 검증 없이 그럴듯하게 제시되는 경우가 많음
- **핵심 원칙: "모르는 것보다 잘못된 정보를 주는 것이 더 나쁘다"**
  → 확인 안 된 정보는 추정/미확인으로 명확히 라벨링해야 함

## 유사 서비스와의 차이 (포지셔닝)
- **Manyfast** (docs.manyfast.io): "이미 만들기로 한 제품"을 PRD→기능명세서→와이어프레임으로
  문서화하는 하류(downstream) 기획 툴. 아이템 단위 관리, MCP로 Cursor/Claude Code에 연동.
- **본 프로젝트**: "만들지 말지, 무엇을 만들지"를 결정하는 상류(upstream) 검증 단계.
  Manyfast가 시작하는 지점(PRD) *이전* 단계를 다룸.
  → 이후 워크플로우 확장 시 Manyfast류 기획 툴이나 Cursor/Claude Code로 결과물을
    넘기는 연결고리가 될 수 있음 (직접 경쟁이 아니라 상류-하류 관계로 설계 가능)

## 핵심 기능 3가지

### 1. 로드맵 에이전트 (오케스트레이터)
아이디어 입력 → 단계별 워크플로우 자동 설계 및 안내
- 시장조사 → 타겟층 설정 → 가설 수립 → 가설 검증 → MVP/MLP 정의 → BM 가정
- 각 단계 산출물이 다음 단계의 입력이 되는 파이프라인 구조
- 대화형 UX로 진행 (일방적 리포트 생성이 아님)

### 2. 가설-검증 프레임워크
- 타겟층/시장/핵심가치를 "검증 가능한 가설" 형태로 변환 (Lean Canvas 방식)
- 각 가설마다 "이걸 검증하려면 무엇이 필요한가"를 구체적으로 제시
  (설문? 인터뷰? 랜딩페이지 스모크테스트? 등)
- MVP/MLP 목표를 가설 검증 결과에 연동
- 비즈니스모델 가정을 구조화 (수익모델, 채널, 비용구조 등)

### 3. 자가검증(Self-verification) 루프 ★ 핵심 차별화
- **출처 등급화**: 1차 자료(공식 통계/학술자료) vs 2차 해석 vs AI 추정치를 구분해서 라벨링
- **교차검증**: 동일 주장에 대해 복수 출처로 재검색, 불일치 탐지
- **신뢰도 명시**: 모든 수치/주장에 확신도 표기, 미확인 정보는 "추정" 또는
  "확인 필요"로 명확히 구분
- **재현 가능한 근거**: 결과물에 출처 링크 항상 첨부, 사용자가 직접 검증 가능하게
- 참고: 이 원리는 Claude가 검색 결과를 인용하고 출처를 명시하는 방식과 유사한 패턴

## 현재 단계
- 형태: 대화형 에이전트로 우선 개발 (리포트 자동생성형이나 에디터형 UI는 이후 고려)
- 기술 스택/아키텍처: 미정
- 검증해야 할 것: 자가검증 루프의 구체적 구현 방식
  (예: 다중 소스 크로스체크 알고리즘, 신뢰도 스코어링 기준 등)

## 경쟁 지형 참고
- ValidatorAI, DimeADozen, IdeaProof, FounderPal, aicofounder — 대부분 빠른 리포트
  생성(TAM/SAM/SOM, SWOT, 투자자용 플랜)에 집중, 근거 검증 장치는 약함
- Perspective AI 등은 AI 모의 고객 인터뷰로 정성적 검증에 강점
- 이 시장의 공통 약점: "그럴듯한 결과물"과 "검증된 결과물"을 구분하지 않음
  → 본 프로젝트가 채울 수 있는 갭

## 다음 논의가 필요한 것
- 자가검증 루프의 구체적 파이프라인 설계 (프롬프트 구조, 도구 연동 방식)
- 대화형 UX의 구체적 플로우 (단계별 질문 설계, 세션 구조)
- MVP 범위 정의 (이 에이전트 자체의 MVP는 무엇인가)
